# 预测阶段分类水平不匹配分析报告

## 一、问题背景

### 1.1 之前的错误描述

在之前的协作分析报告（`statsmodels_patsy协作分析.md`）第 1202 行，存在以下错误描述：

> **2. 分类变量的一致性**：预测时分类变量可以包含训练时未见过的类别，但这些类别会被编码为全 0 列

### 1.2 重新核对的结论

经过对源代码和官方文档/issue 的重新核对，**上述描述与实际实现完全不符**：

| 项目 | 错误描述 | 实际实现 |
|------|---------|---------|
| 未见过的分类水平处理 | 编码为全 0 列 | **抛出异常，无法继续预测** |
| 错误类型 | 无异常 | `PatsyError` 或 `ValueError` |
| 用户体验 | 静默处理（可能产生错误结果） | 显式报错，阻止错误预测 |

## 二、正常预测路径分析

### 2.1 正常预测流程

当使用公式接口训练的模型进行预测时，正常流程如下：

```

         │
         ├──► 检查: hasattr(self.model, "formula")?
         │       │
         │       ├──► 是（公式接口创建的模型）
         │       │       │
         │       │       ▼
         │       │   mgr = FormulaManager()

         │       │       │

         │       │       │       patsy.dmatrix(model_spec, new_data, ...)

         │       │       │           检查新数据中的分类值是否匹配
```

#### 2.2.3 FormulaManager 处理 (`_manager.py:417-493`)

```python
def get_matrices(
    self,
    formula,
    data,
    eval_env=0,
    pandas=True,
    na_action=None,
    prediction=False,  # 预测模式
):
    if self._using_patsy:
        return_type = "dataframe" if pandas else "matrix"
        kwargs = {}
        if na_action:
            kwargs["NA_action"] = na_action
        
        # 关键：如果 formula 是 DesignInfo 或 ModelDesc，
        # 使用 patsy.dmatrix 直接处理
        if (
            isinstance(
                formula, (patsy.design_info.DesignInfo, patsy.desc.ModelDesc)
            )
            or "~" not in formula
            or formula.strip().startswith("~")
        ):
            output = patsy.dmatrix(
                formula, data, eval_env=_eval_env, 
                return_type=return_type, **kwargs
            )
        else:
            output = patsy.dmatrices(...)
        
        # 提取 DesignInfo
        if isinstance(output, tuple):
            self._spec = output[1].design_info
        else:
            self._spec = output.design_info
        
        return output
```

### 2.3 DesignInfo 的关键作用

在训练阶段，Patsy 会保存以下关键信息到 `DesignInfo`：

| 属性 | 用途 | 预测时的作用 |
|------|------|-------------|
| `factor_infos` | 每个因子的类型信息 | 检查分类变量的 `levels`（允许的类别） |
| `column_names` | 设计矩阵列名 | 确保列顺序一致 |
| `term_codings` | 项的编码信息 | 使用相同的对比矩阵 |

**关键**：`factor_infos` 中保存了训练时见到的所有分类水平（levels），预测时会严格检查新数据中的分类值是否在这些 levels 中。

## 三、异常路径分析（分类水平不匹配）

### 3.1 完整错误路径

当预测数据包含训练时未见过的分类水平时，错误路径如下：

```

         │

Results.predict() → _transform_predict_exog()
         │

         │

patsy.dmatrix(model_spec, new_data, ...)

├──► 从 model_spec.factor_infos 获取允许的 levels

├──► 遍历新数据中的分类值
```

#### 3.2.1 第一层：Patsy 核心层（错误源头）

- 新数据中的分类值不在 `factor_infos[factor].levels` 中

### 3.3 相关 GitHub Issue 确认

以下是来自官方仓库的确认信息：

#### Issue #805：nan with categorical in formula

**问题描述**：
```

            object nan does not match any of the expected levels
```

**来源**：https://github.com/statsmodels/statsmodels/issues/805

#### Issue #110（Patsy 官方）：Better handling for unrecognized categorical levels?

**关键讨论**：

> "I think the only reasonable solution besides raising an exception would be to treat it as missing value."
> 
> — Patsy 维护者

> "There's a request here to add an option so that when an unrecognized categorical level is encountered, it should be encoded as all-zeros, which is apparently similar to what scikit-learn's DictVectorizer does."

> "But AFAICT this would lead to terribly incorrect behavior in any kind of linear-ish model..."

> — Patsy 维护者

**核心结论**：
1. **"编码为全零"是一个功能请求**，而非现有功能
2. Patsy 维护者认为这会在线性模型中导致**严重错误的行为**
3. 默认行为是**抛出异常**，而不是静默处理

## 五、与之前错误描述的关键差异

### 5.1 错误描述的来源推测

之前报告中"编码为全 0 列"的描述可能来源于：

1. **scikit-learn 的行为**：`DictVectorizer` 确实会将未见过的类别编码为全零向量
2. **Patsy 的功能请求**：GitHub Issue #110 讨论了是否要添加这个功能（但未实现）

### 5.2 关键差异对比

| 项目 | 错误描述（之前） | 实际实现（正确） |
|------|-----------------|-----------------|
| **未见过的分类水平处理** | 编码为全 0 列 | **抛出异常** |
| **异常类型** | 无异常 | `PatsyError`（Patsy 引擎）或 `ValueError`（formulaic 引擎） |
| **预测是否继续** | 是（静默处理） | **否**（阻止继续） |
| **对模型的影响** | 可能产生错误预测 | **立即失败，避免错误结果** |
| **是否符合线性模型假设** | 不符合（全零等价于参考类别或均值为 0） | **符合**（不做无根据的假设） |

### 5.3 为什么"编码为全零"是危险的

Patsy 维护者在 Issue #110 中详细解释了为什么编码为全零在线性模型中是危险的：

#### 情况 1：Treatment 编码（默认）

公式：`y ~ C(city) + bedrooms + baths`

- 训练时见过的城市：`['NewYork', 'LA', 'Chicago']`
- 参考水平：`NewYork`（第一个）
- 设计矩阵列：`Intercept, C(city)[T.LA], C(city)[T.Chicago], bedrooms, baths`

**如果新城市 'Seattle' 被编码为全零**：
- `C(city)[T.LA] = 0`
- `C(city)[T.Chicago] = 0`
- 这等价于 `Intercept` 单独作用
- 即：假设 Seattle 的行为与参考城市 NewYork 完全相同

**问题**：这是一个毫无根据的假设，会导致错误的预测。

#### 情况 2：满秩编码（无截距）

公式：`y ~ 0 + C(city) + bedrooms + baths`

- 设计矩阵列：`C(city)[NewYork], C(city)[LA], C(city)[Chicago], bedrooms, baths`

**如果新城市 'Seattle' 被编码为全零**：
- 所有城市系数都为 0
- 这等价于假设 Seattle 的均值为 0（在链接函数尺度上）

**问题**：这是一个更糟糕的假设，几乎可以肯定是错误的。

## 六、实际使用建议

### 6.1 预防措施

在训练阶段预防分类水平不匹配问题：

```python
# 方案 1：将低频率类别合并为 'Other'
import pandas as pd

def merge_low_freq_categories(series, threshold=0.05, other_label='Other'):
    """
    将频率低于阈值的类别合并为 'Other'
    """
    freq = series.value_counts(normalize=True)
    to_merge = freq[freq < threshold].index
    return series.replace(to_merge, other_label)

# 使用示例
df['city_merged'] = merge_low_freq_categories(df['city'], threshold=0.01)
# 然后使用 city_merged 训练模型
```

### 6.2 预测时的异常处理

在代码中显式捕获和处理分类水平不匹配异常：

```python
import pandas as pd
import statsmodels.formula.api as smf

# 训练模型（假设 'city' 是分类变量）
model = smf.ols('price ~ city + bedrooms + sqft', data=train_df)
results = model.fit()

# 预测时捕获异常
def safe_predict(results, new_data):
    """
    安全的预测函数，处理分类水平不匹配异常
    """
    try:
        return results.predict(new_data)
    except Exception as e:
        # 检查是否是分类水平不匹配错误
        error_msg = str(e)
        if "does not match any of the expected levels" in error_msg:
            # 提取具体信息
            import re
            # 解析错误信息
            # 格式: "observation with value 'X' does not match any of the expected levels (expected: ['A', 'B'])"
            value_match = re.search(r"value '([^']+)'", error_msg)
            levels_match = re.search(r"expected: \[([^\]]+)\]", error_msg)
            
            bad_value = value_match.group(1) if value_match else "unknown"
            expected_levels = levels_match.group(1) if levels_match else "unknown"
            
            raise ValueError(
                f"预测数据包含未见过的分类值 '{bad_value}'。\n"
                f"训练时见过的类别: {expected_levels}\n"
                f"建议：在训练前将低频率类别合并为 'Other'，或者在预测前过滤/替换未知类别。"
            ) from e
        else:
            # 其他错误，重新抛出
            raise

# 使用示例
test_df = pd.DataFrame({
    'city': ['NewYork', 'LA', 'Seattle'],  # 'Seattle' 未见过
    'bedrooms': [3, 2, 4],
    'sqft': [1500, 1200, 2000]
})

try:
    predictions = safe_predict(results, test_df)
except ValueError as e:
    print(f"预测失败: {e}")
    # 处理逻辑：例如，跳过未知类别，或者使用默认值
```

## 七、关键发现总结

### 7.1 核心修正

**之前的错误描述**：
> "预测时分类变量可以包含训练时未见过的类别，但这些类别会被编码为全 0 列"

**正确的实际实现**：
> "预测时分类变量**不能**包含训练时未见过的类别。如果存在，**Patsy 会抛出异常**，预测无法继续。Statsmodels 会捕获并封装这个异常，提供更友好的错误信息。"

### 7.2 三层职责边界

| 层级 | 组件 | 职责 | 分类水平不匹配时的行为 |
|------|------|------|----------------------|
| **第一层** | **Patsy/formulaic** | 公式解析、设计矩阵生成 | 检测到不匹配 → 抛出原始异常 |
| **第二层** | **Statsmodels FormulaManager** | 引擎抽象、统一接口 | 透传异常（不额外处理） |
| **第三层** | **Statsmodels _transform_predict_exog** | 预测时的数据转换 | 捕获异常 → 封装错误信息 → 重新抛出 |

### 7.3 设计决策的合理性

Patsy 选择"抛出异常"而非"静默处理"是合理的：

1. **避免错误预测**：在线性模型中，对未见过的类别做出任何假设（如全零）都是危险的
2. **明确的错误反馈**：用户立即知道问题所在，而不是得到错误的预测结果
3. **强制数据预处理**：促使用户在训练阶段处理好分类变量（如合并低频率类别）

### 7.4 与 scikit-learn 的对比

| 框架 | 未见过的分类值处理 | 适用场景 |
|------|------------------|---------|
| **Patsy + Statsmodels** | 抛出异常 | 统计建模、推断（需要严格的假设检验） |
| **scikit-learn DictVectorizer** | 编码为全零 | 机器学习、预测（注重鲁棒性） |

**关键差异**：
- Statsmodels 用于**统计推断**，需要严格的模型假设
- scikit-learn 用于**预测任务**，注重生产环境的鲁棒性
